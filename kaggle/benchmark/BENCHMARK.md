# qmlf Kaggle Benchmark — task manifest

Private benchmark measuring whether an LLM can do **professional-grade quantum
machine learning with qmlf** — correctly, reproducibly, and honestly — rather
than merely call a quantum API. Fifteen tasks, six tiers. Every task is graded
from **executed artifacts** (the model's code is run, or its configuration is
built and measured); nothing is self-reported. Every threshold traces to a
measured reference in `references/references.json`; every naive baseline
fails, every known-good ceiling passes, and every trap is exercised by
`validate_local.py` with zero LLM calls.

Namespace: all tasks are `qmlfb-*` on the `hemakarapu` account. Dataset
attachment: `hemakarapu/qmlf-wheelhouse` (qmlf 1.4.0, offline install ~15s;
public-repo fallback built in). The collection itself is curated in the Kaggle
web UI (the CLI manages individual tasks only).

## Public exam, private answer key

The 92 task files in `tasks/` are the exam and are publishable. The generator
(`private/suite.py`, which embeds a working solution per family), the stub
validators, and **22 held-out variants** live in `private/`, which is
git-ignored on `main` and committed only on a private branch
(`private/GIT_PLAN.md`). The held-out set is the contamination control: the
same families with different seeds, never published, run alongside every
public evaluation -- a widening public-vs-held-out gap means the answers
reached training data. The original pilot task is already on the public repo
with its sweep table and is kept as a **canary** for the same purpose.

## Scale: 114 tasks (92 public + 22 held-out)

The 15 hand-built tasks below are the pilot. The suite is generated by
`suite.py` from **20 task families × parametrised variants**: 115 candidates
were measured, **16 were auto-pruned** because their naive→ceiling gap was too
small or the ceiling could not clear the bar (no manufactured difficulty), and
**99 were built** — every one with its own reference sweep, stamped thresholds,
and a naive/ceiling stub check (198 runs, all verdicts as expected). The full
per-task table is in [`SUITE.md`](SUITE.md).

| family | variants | what varies |
|---|---|---|
| conc, proj, ard, entangle, bwselect, diagnostics, graph | 40 | data regime (blobs/moons/circles/xor/shift/quantiles), 4–12 qubits, selection principle, kernel family, backend |
| advantage, honesty | 11 | data geometry → different screen verdicts; different classical baselines |
| budget, transpile, nisqplan | 13 | sample count × hardware budget; circuit width/reps/entanglement × optimizer strength |
| mitigate, depol | 10 | state count, noise strength, readout error, scale factors; known-channel inversion |
| vqe, chem, determinism | 9 | geometries/charges/atom counts; which stochastic component must be made reproducible |
| industrial, regression | 7 | real datasets (breast cancer, wine, iris, digits 3v8); physical targets (oscillator, sinc, Friedman, quadratic) |
| debug, federated, viz | 14 | **seven distinct planted-bug sets** (generated broken scripts); cohort sizes; which figure |

Regenerate / extend:

```bash
cd kaggle/benchmark
PYTHONPATH=../.. python suite.py refs       # measure every variant, prune weak ones
python suite.py build                        # render kept variants to tasks/
PYTHONPATH=../.. python suite.py validate    # naive must FAIL, ceiling must PASS
python suite.py manifest                     # SUITE.md
./push_suite.sh                              # paced private push (<=3 in flight)
```

Adding a family is ~60 lines: a `score(...)` source block, a `reference(v, data)`
that returns thresholds and `keep`, a prompt, and naive/ceiling candidates.

## Interaction modes

| mode | what the model returns | how it is graded |
|---|---|---|
| **code** | one `python` fence defining a named function | `_run_model_function` execs it under a wall-clock limit, calls it on hidden data, measures the result |
| **plan** | a pydantic configuration object | the grader builds exactly that configuration with qmlf and measures it |

## The tasks

### Tier A — Kernel geometry and concentration
*Thanasilp et al. 2024; Shaydulin & Wild 2022; Huang et al. 2021*

| task | mode | the skill | naive → bar → ceiling |
|---|---|---|---|
| `qmlfb-kernel-concentration-rescue` | plan | recognise fidelity-kernel concentration; tune bandwidth; avoid the `fidelity_quantum_kernel` bypass | 0.40 → 0.70 + offdiag ≥ 0.10 → 0.80 |
| `qmlfb-projected-kernel-at-scale` | code | escape concentration at 10 qubits **without** reducing dimensionality | 0.30 (offdiag 0.0010) → 0.85 + offdiag ≥ 0.10 → 0.93 |
| `qmlfb-ard-noise-suppression` | code | discover hidden noise features; suppress them with a post-whitening per-feature bandwidth | best scalar 0.643 → 0.78 + noise/informative ≤ 0.30 → 0.857 |
| `qmlfb-entanglement-is-not-free` | plan | reach the bar with zero entangling gates (Bowles/Schuld: entanglement often buys nothing) | zz 0.92/40 gates → 0.90 + 0 gates → z 0.96/0 |

### Tier B — Judgment and honesty
*Huang et al. 2021; Bowles, Ahmed & Schuld 2024*

| task | mode | the skill | grading |
|---|---|---|---|
| `qmlfb-advantage-screen-judgment` | code | run the geometric-difference screen on two datasets; classify verdict; make the conservative call | g within 15% of reference; category + recommendation exact, both datasets |
| `qmlfb-classical-baseline-honesty` | code | competent classical baseline **and** tuned quantum model; calibrated estimates; consistent verdict | both ≥ bar; winner follows own estimates; estimates ≤ reality + 12 pts |

### Tier C — Hardware economics
| task | mode | the skill | grading |
|---|---|---|---|
| `qmlfb-circuit-budget-nystrom` | code | fit a 25,000-circuit hardware budget with Nyström landmarks (320 rows need 51,040 pairwise) | budget respected; grader-built Nyström features reach ≥ 0.58 (m=70 gives 0.637) |
| `qmlfb-nisq-transpile-honesty` | code | report REAL transpiled resources, label the analytic projection as an estimate | measured depth/2q = 40/40 (estimate claims 16) |

### Tier D — Noise and mitigation
| task | mode | the skill | grading |
|---|---|---|---|
| `qmlfb-mitigation-pipeline` | code | readout-correct each noise scale, then ZNE across scales, in the right order and shapes | L1 to ideal ≤ 0.035 (raw 0.117, readout-only 0.060, pipeline 0.0225) |

### Tier E — Variational
| task | mode | the skill | grading |
|---|---|---|---|
| `qmlfb-qnn-reproducible-training` | code | train the variational layer reproducibly; return an inference-deterministic model | identical loss curves + predictions across seeded runs; two forward passes of the returned model identical; loss ↓ ≥ 20% (ref 37%) |
| `qmlfb-vqe-variational-principle` | code | exact energy + deterministic VQE obeying the variational bound | exact = -3.2716 to 1e-9; VQE repeat-identical; in [-12.743, +0.3] |

### Tier F — Industrial pipelines
| task | mode | the skill | grading |
|---|---|---|---|
| `qmlfb-industrial-wide-data-pipeline` | plan | production config on real 30-feature diagnostics data: reduce, encode, tune | ≥ 0.88 + not severely concentrated (naive 0.62, auto 0.92, classical 0.98) |
| `qmlfb-regression-physical-model` | plan | quantum kernel ridge on a damped oscillator; pick the family that generalises | R² ≥ 0.40 (fidelity auto 0.24, projected 0.54) |
| `qmlfb-debug-broken-pipeline` | code | repair four planted bugs (width mismatch, QSVC bypass, mis-cased strategy, 1-D ZNE) | runs; ≥ 0.90 (bypass gives 0.45); valid ZNE output |
| `qmlfb-federated-partial-participation` | code | exact sample-weighted FedAvg under partial participation | equals reference to 1e-9; unweighted mean explicitly fails |

```bash

```

## Sandbox lesson learned

Two tasks initially died with "notebook completed but no run output": their
result dicts contained a `numpy.bool_`, which `json.dumps` rejects, so kbench
could not write the run file. Every generated task now routes its return
value through `_jsonable()` (in `common.py`). If a task ever shows
`Kernel_Without_Run`, check the return types first.

## Known account clutter

The first push attempt hit the concurrency limit and left nine orphaned task
shells under the old `qmlf-*` names ("exists but has no source kernel";
server-side delete is not yet supported) plus five completed duplicates.
They are harmless; hide them in the web UI when curating the collection.
Three zero-quota probe tasks (`qmlfb-probe-*`, `qmlf-torch-probe`) also exist;
they never call the LLM and are useful to re-run after any Kaggle image change.
